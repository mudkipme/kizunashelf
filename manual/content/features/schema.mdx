The schema — `KizunaShelf/config.yaml`, the source of truth for what everything *means* — is edited in **Settings** on web/desktop and **More → Vault Schema** on iOS. Because the schema lives in the vault, an edit on one device reaches every device with the next sync.

## Two editors, one file

- **The structured form** works with the typed schema: types, ordered field lists, enum options, roles, provider wiring — validated as you go, with vault-path autocomplete for folder fields (desktop adds a native folder picker).
- **The raw YAML editor** (web/desktop) edits the document directly. It validates the complete document strictly and writes your text **verbatim, preserving comments and formatting** — the editor for hand-tuned configs. (On iOS, edit the file in a text editor when you need comment-level control.)

The form covers the whole config: vault paths (`taxonomyRoot`, `assetRoot`), [daily notes](./log.mdx#configuring-daily-notes), and every type with its fields. What each option means is the [reference](../reference/config.md)'s job; how to design a type well is the [Defining your own type](../guides/defining-a-type.md) guide.

## Adding a built-in type

**Add a built-in type** opens the same [preset picker](../reference/presets.md) as onboarding: pick *Anime*, *Games*, *Books*, …, and a fully-wired type is merged into your schema — fields, roles, provider mappings, seeded in your language. Presets whose relation targets you also have (or add together) keep those relations; colliding ids get suffixed rather than overwriting. Everything a preset adds is ordinary schema you can immediately edit. After adding types, use **Add suggested lists** on [Home](./home.mdx) to create matching smart lists.

## Guardrails

- Settings writes are gated separately from content writes: self-hosted web disables them for non-loopback hosts unless `KIZUNASHELF_SETTINGS_WRITABLE=true`; desktop and iOS treat an opened vault as schema-writable.
- Schema edits never rewrite your entities. Removing a field's declaration stops the UI from *interpreting* it — the frontmatter itself stays in every file, and re-declaring the field brings its meaning back.
- Be careful with simultaneous schema edits from two devices; the config is one shared file. See [Avoiding sync conflicts](../guides/syncing.md#avoiding-sync-conflicts).
